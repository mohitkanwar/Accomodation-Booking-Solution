# Roadmap and Workshop Outputs

## Recommended increments

### Phase 0 — Commercial and technical validation

Confirm affiliate eligibility, API capability and version, payment flow,
sandbox access, privacy position, operating model, and a thin technical spike.
This is a hard gate for integrated booking.

### Phase 1 — Search and request

Deliver destinations, policy resolution, search, comparison, compliance,
request submission, operator queue, manual completion, notification,
administration, and audit. Validate demand and policy before putting payment
and supplier order creation on the critical path.

### Phase 2 — Integrated operator booking

Add live recheck, order preview and creation, confirmation, failure recovery,
and reconciliation.

### Phase 3 — Service and optimise

Add supported cancellation/modification, financial reconciliation, dashboards,
policy analytics, preferred options, automation, and future supplier
abstraction.

## Required workshop outputs

1. Agreed problem statement, outcomes, and success measures.
2. Scope, MVP boundary, and prioritised capability backlog.
3. User, operator, and exception journeys.
4. Role, policy, payment, and operating models.
5. Booking.com capability assessment and validation plan.
6. Agreed solution context, lifecycle, and data ownership.
7. Security, privacy, NFR, and operational-readiness requirements.
8. Decision, risk, assumption, issue, and dependency register.
9. Delivery roadmap, owners, next actions, and review dates.

## Close-out checklist

- Record decisions and dissent.
- Assign owners and dates to every action.
- Identify which gates block funding or delivery.
- Schedule validation playback with evidence.
- Baseline the MVP only after the blocking decisions are resolved.
