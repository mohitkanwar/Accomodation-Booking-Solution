# Versioning and deprecation

Booking.com API versions and internal B2C contracts evolve independently.

The adapter isolates v3.1, v3.2, beta, or later supplier differences. The
approved production version is an explicit onboarding decision.

Breaking internal API or event changes require a new version, documented
migration period, compatibility testing, consumer adoption tracking, and
deprecation date. Detailed retention and support windows are not yet defined.
