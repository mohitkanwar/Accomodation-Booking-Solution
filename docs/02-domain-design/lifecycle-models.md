# Lifecycle models

## Request lifecycle

```text
stateDiagram-v2
  [*] --> DRAFT
  DRAFT --> SUBMITTED
  SUBMITTED --> NEEDS_INFORMATION
  NEEDS_INFORMATION --> SUBMITTED
  SUBMITTED --> REJECTED
  SUBMITTED --> EXCEPTION_REVIEW
  EXCEPTION_REVIEW --> REJECTED
  EXCEPTION_REVIEW --> APPROVED
  SUBMITTED --> APPROVED
  APPROVED --> BOOKING_IN_PROGRESS
  BOOKING_IN_PROGRESS --> BOOKING_FAILED
  BOOKING_IN_PROGRESS --> BOOKED
  BOOKING_FAILED --> BOOKING_IN_PROGRESS
  BOOKED --> CANCELLATION_REQUESTED
  CANCELLATION_REQUESTED --> CANCELLATION_FAILED
  CANCELLATION_REQUESTED --> CANCELLED
  BOOKED --> COMPLETED
```

The workflow must not collapse `APPROVED`, `BOOKING_IN_PROGRESS`, and `BOOKED`
into a single state.
